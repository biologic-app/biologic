# Access Matrix

> Нормативная матрица ролей, действий и областей видимости. Пароли из исходного описания намеренно не сохранены в wiki, чтобы не фиксировать секреты в репозитории.

## Actions

| Код | Действие |
|---|---|
| `C` | Create — создание. |
| `R` | Read — чтение / просмотр. |
| `U` | Update — редактирование. |
| `D` | Delete — soft delete. |
| `IMP` | Import — импорт направления из файла. |
| `REG` | Register — регистрация образца / направления. |
| `REJ` | Reject — отклонение / брак. |
| `CNF` | Confirm — подтверждение исследования `draft -> ordered`. |
| `STR` | Start — взять в работу. |
| `RES` | Result — внести результат испытания. |
| `REQ` | Requeue — вернуть испытание в очередь. |
| `CLO` | Close — закрыть образец и установить вердикт. |
| `MRK` | Mark as read — отметить уведомление прочитанным. |
| `HID` | Hide — скрыть уведомление. |

## Scope Marks

| Метка | Описание |
|---|---|
| `^1` | Только по своим созданным записям. |
| `^2` | Только в рамках своей лаборатории. |
| `^3` | Только в рамках своего филиала. |
| `^4` | Только пока запись в статусе `draft`. |
| `^5` | Только для указанного идентификатора. |
| `^6` | Видит протоколы, в которые входит хотя бы один его образец. |
| `^7` | Только свои уведомления. |

НФ имеет настраиваемый scope: только свой филиал или все филиалы через `user_scopes`.

## Resource Access Summary

| Ресурс | Основные права |
|---|---|
| `users` | АП управляет пользователями в филиале; остальные роли читают пользователей в пределах scope; НФ читает по настройке scope. |
| `roles`, `user_scopes`, `role_permissions`, `permissions` | Полное управление у РАЗ и АП; остальные роли без доступа. |
| `branches`, `labs` | РАЗ имеет полный доступ; НФ читает структуру филиала; РЕГ/СВ/НЛ читают labs в рамках филиала. |
| `direction_statuses`, `sample_statuses`, `research_statuses`, `test_statuses` | РАЗ управляет; операционные роли читают. |
| `sample_types`, `protocol_types` | РАЗ управляет; операционные роли читают. |
| `conclusions`, `objects` | РЕГ создаёт, читает и обновляет в рамках филиала; остальные читают по scope. |
| `research_goals`, `indicators` | НЛ управляет в своей лаборатории; АЛ/ВЛ читают в своей лаборатории; РЕГ читает в филиале. |
| `directions` | РЕГ создаёт, импортирует, редактирует и регистрирует draft в филиале; СВ читает свои; лабораторные роли читают в своей лаборатории; НФ читает филиал. |
| `samples` | РЕГ создаёт, регистрирует и отклоняет; ВЛ/НЛ читают и могут отклонять в своей лаборатории; НЛ закрывает; СВ/НФ читают по scope. |
| `research` | РЕГ создаёт и отклоняет в филиале; ВЛ/НЛ читают, подтверждают, стартуют и отклоняют в лаборатории; АЛ читает. |
| `tests` | ВЛ/НЛ читают, стартуют, вносят результат, возвращают в очередь и отклоняют в лаборатории; АЛ читает. |
| `protocols` | РЕГ создаёт, читает и обновляет; СВ видит протоколы со своими образцами; лаборатория и НФ читают по scope. |
| `history` | Все роли читают историю только по разрешённой сущности или указанному идентификатору. |
| `alerts` | СВ, РЕГ, ВЛ, НЛ, НФ читают свои уведомления и могут `MRK`/`HID`; АП и АЛ операционные уведомления не получают. |
