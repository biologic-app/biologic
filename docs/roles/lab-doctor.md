# Врач лаборатории (lab_doctor)

## Назначение
Врач-лаборант — центральная операционная роль лабораторного процесса. Он
подтверждает назначенные регистратором исследования, берёт их в работу и
выполняет отдельные испытания (тесты): вносит результаты измерений, возвращает
испытания в очередь или отклоняет их. Может забраковать образец при
обнаружении непригодности материала.

## Действия

| Действие | Ресурс | Право | Scope | Статусный переход |
|---|---|---|---|---|
| Подтвердить исследование | `research` | `confirm` (CNF) | own_lab² | `draft` → `ordered` |
| Отклонить исследование | `research` | `reject` (REJ) | own_lab² | `draft` / `ordered` → `rejected` |
| Взять исследование в работу | `research` | `start` (STR) | own_lab² | `ordered` → `in_progress` |
| Взять испытание в работу | `tests` | `start` (STR) | own_lab² | `queued` → `in_progress` |
| Внести результат испытания | `tests` | `result` (RES) | own_lab² | `in_progress` → `completed` |
| Вернуть испытание в очередь | `tests` | `requeue` (REQ) | own_lab² | `in_progress` → `queued` |
| Отклонить испытание | `tests` | `reject` (REJ) | own_lab² | `queued` / `in_progress` → `rejected` |
| Забраковать образец (брак в лаборатории) | `samples` | `reject` (REJ) | own_lab² | `pending` / `registered` / `in_progress` → `rejected` |
| Просмотреть направления / образцы / протоколы / заключения | `directions`, `samples`, `protocols`, `conclusions` | `read` (R) | own_lab² | — |
| Просмотреть технический аудит | `history` | `read` (R) | по указанному `entity_id` | — |
| Управление своими уведомлениями | `alerts` | `read`, `mark-read`, `hide` | own | — |

> Легенда: ² = «только в рамках своей лаборатории» (`../product/role-access-matrix.md`).
> Врач-лаборант **не управляет** справочниками показателей (`indicators`) и
> целей исследований (`research_goals`) — это зона начальника лаборатории
> (`lab-chief.md`); не имеет `directions.register`/`create`, `samples.create`,
> `samples.close`, `protocols.create`.

## Сценарии

Подробный E2E-сценарий — `../frontend/flows/lab-doctor.flow.md`
(видео `../frontend/flows/videos/lab-doctor-flow.webm`).

1. Видит список исследований в статусе `draft`, назначенных на его
   лабораторию (страница «Исследования»).
2. Подтверждает исследование (`draft → ordered`) либо отклоняет с указанием
   причины (`draft → rejected`).
3. Берёт исследование в работу (`ordered → in_progress`) — серверным побочным
   эффектом образец переходит `registered → in_progress`, а направление —
   `registered → in_progress`.
4. По каждому исследованию проводит испытания:
   - берёт испытание в работу (`queued → in_progress`);
   - вносит результат измерения — поля «Значение» (обязательно) и «Норма»
     (`in_progress → completed`);
   - при необходимости возвращает испытание в очередь (`in_progress →
     queued`) или отклоняет его с указанием причины.
5. Когда все испытания исследования завершены (terminal-статусы), система
   **автоматически** переводит исследование `in_progress → completed`, а если
   у образца не осталось незавершённых исследований — образец переходит в
   `analyzed`. Каскад требует, чтобы образец уже был зарегистрирован и в
   работе — иначе переход отклоняется с `409 invalid_status_transition`.
6. Может забраковать образец при обнаружении непригодности материала
   (`pending`/`registered`/`in_progress` → `rejected`) — создаёт SSE-уведомление
   владельцу направления и запись технического аудита.

## Границы (scope)
Врач-лаборант видит и изменяет образцы, исследования и испытания **только
своей лаборатории** (`own_lab`). Не может регистрировать направления, создавать
образцы напрямую, закрывать образцы (`analyzed → completed`) или вести
лабораторные справочники — все три относятся к зоне начальника лаборатории.

> ⚠️ **(уточнить, известные ограничения реализации):** автоматического
> скоупинга по лаборатории в списках нет (сужение только через фильтр
> «Лаборатория»); RBAC на уровне API отсутствует — авторизация полностью на
> фронте (см. `../frontend/flows/lab-doctor.flow.md` §8).

## Definition of Done
- Подтверждение / взятие в работу / отклонение исследования и весь цикл
  испытаний (start / complete / requeue / reject) работают на реальном API.
- Каскадное авто-завершение исследования и перевод образца в `analyzed`
  воспроизводится без ручного действия врача.
- Брак образца создаёт SSE-уведомление и запись технического аудита.
- `bun run lint typecheck build` зелёные; сценарий проверен e2e-тестом
  `tests/e2e/lab-doctor-lifecycle.spec.ts` и разделами 5 «Исследования», 6
  «Тесты» в `../product/frontend-user-stories.md`.
