# Начальник лаборатории (lab_chief)

## Назначение
Начальник лаборатории управляет работой лаборатории целиком: обладает всеми
правами врача-лаборанта в своей лаборатории, дополнительно закрывает образцы
после завершения всех исследований (устанавливает финальный вердикт) и ведёт
лабораторные справочники — показатели (`indicators`) и цели исследований
(`research_goals`).

## Действия

| Действие | Ресурс | Право | Scope | Статусный переход |
|---|---|---|---|---|
| Все действия врача-лаборанта (см. `lab-doctor.md`) | `research`, `tests`, `samples` | CNF, STR, RES, REQ, REJ | own_lab² | см. `lab-doctor.md` |
| Закрыть образец, установить вердикт | `samples` | `close` (CLO) | own_lab² | `analyzed` → `completed` |
| Назначить новые испытания на закрытое исследование | `tests` | `create` (C) | own_lab² | `completed` → `in_progress` (исследование), `analyzed` → `in_progress` (образец) |
| Вести справочник показателей | `indicators` | `create` / `read` / `update` / `delete` (C,R,U,D) | own_lab² | — |
| Вести справочник целей исследований | `research_goals` | `create` / `read` / `update` / `delete` (C,R,U,D) | own_lab² | — |
| Просмотреть все образцы / исследования / протоколы лаборатории | `samples`, `research`, `protocols` | `read` (R) | own_lab² | — |
| Просмотреть технический аудит | `history` | `read` (R) | по указанному `entity_id` | — |
| Управление своими уведомлениями | `alerts` | `read`, `mark-read`, `hide` | own | — |

> Легенда: ² = «только в рамках своей лаборатории» (`../product/role-access-matrix.md`).

## Сценарии
1. Подтверждает или отклоняет исследования (`draft → ordered` / `rejected`).
2. При необходимости сам проводит испытания, замещая врача-лаборанта — все
   действия ВЛ доступны без ограничений.
3. После завершения всех исследований по образцу (образец в статусе
   `analyzed`) открывает карточку образца и **закрывает** его: `analyzed →
   completed`, обязательно устанавливает `verdict` («соответствует» / «не
   соответствует»).
4. Если требуется повторное исследование — назначает новые испытания, тогда
   образец автоматически возвращается `analyzed → in_progress`, а исследование
   `completed → in_progress`.
5. Ведёт справочники показателей (`indicators`) и целей исследований
   (`research_goals`) в рамках своей лаборатории — используются при
   назначении исследований регистратором (`assign-research`).
6. Получает уведомления о браке образцов, критических вердиктах и
   приближающихся дедлайнах — см. таблицу уведомлений в
   `../product/work-processes-by-roles.md`, раздел 5.

## Границы (scope)
Начальник лаборатории действует **в рамках своей лаборатории** (`own_lab`) —
как и врач-лаборант, но с дополнительным правом финального закрытия образца
и ведения лабораторных справочников. Не имеет доступа к регистрации
направлений, созданию образцов «с нуля» или управлению пользователями/ролями.

> ⚠️ **(уточнить, известное ограничение реализации):** автоматического
> скоупинга по лаборатории в списках нет; RBAC на уровне API отсутствует —
> см. аналогичные ограничения в `../frontend/flows/lab-doctor.flow.md` §8,
> применимые и к начальнику лаборатории как расширению роли ВЛ.

## Definition of Done
- Закрытие образца (`analyzed → completed`) требует обязательного вердикта и
  фиксируется в техническом аудите.
- Назначение нового исследования на закрытый образец корректно возвращает
  образец и исследование в `in_progress`.
- CRUD справочников `indicators` и `research_goals` работает в рамках своей
  лаборатории и отражается в форме назначения исследования регистратором.
- `bun run lint typecheck build` зелёные; сценарий проверен на реальном API —
  см. разделы 5 «Исследования», 6 «Тесты», 7 «Справочники» в
  `../product/frontend-user-stories.md`.
