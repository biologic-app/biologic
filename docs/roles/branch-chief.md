# Начальник филиала (branch_chief)

## Назначение
Начальник филиала контролирует работу всего филиала: просматривает
направления, образцы и протоколы по всем лабораториям филиала, получает
уведомления о критических событиях (брак, отрицательный вердикт, просроченные
дедлайны). Роль **не вмешивается** в операционные процессы напрямую — доступ
только на чтение.

## Действия

| Действие | Ресурс | Право | Scope | Статусный переход |
|---|---|---|---|---|
| Просмотреть направления | `directions` | `read` (R) | own_branch³ (настраиваемый — см. «Границы») | — |
| Просмотреть образцы | `samples` | `read` (R) | own_branch³ | — |
| Просмотреть протоколы | `protocols` | `read` (R) | own_branch³ | — |
| Просмотреть объекты / лаборатории / заключения (справочно) | `objects`, `labs`, `conclusions` | `read` (R) | own_branch³ | — |
| Просмотреть пользователей филиала | `users` | `read` (R) | own_branch³ (полный список — при глобальном scope) | — |
| Просмотреть технический аудит | `history` | `read` (R) | по указанному `entity_id` | — |
| Управление своими уведомлениями | `alerts` | `read`, `mark-read`, `hide` | own | — |

> Легенда: ³ = «в рамках своего филиала» (`../product/role-access-matrix.md`).
> Начальник филиала **не имеет доступа** к исследованиям (`research`),
> испытаниям (`tests`), заключениям как редактируемому справочнику
> (`conclusions` — только чтение) и лабораторным справочникам
> (`indicators`, `research_goals` — нет доступа).

## Сценарии
1. Получает уведомления о критических событиях:
   - образец признан браком (`rejected`);
   - финальный вердикт по образцу — «не соответствует»;
   - просроченные дедлайны по направлениям.
2. Открывает дашборд филиала: сводная статистика — активные направления,
   образцы по статусам, просроченные дедлайны, браки за период (см.
   «Главный экран» в `../product/work-processes-by-roles.md`, раздел 6).
3. Просматривает направления (`draft → completed`), образцы и протоколы по
   всем лабораториям своего филиала — только чтение, без возможности
   вмешаться в статусы.
4. Переходит из ленты уведомлений напрямую к карточке проблемного образца
   или направления.

## Границы (scope)
Начальник филиала видит данные **в рамках своего филиала** (`own_branch`).

> **(уточнить):** согласно `../product/role-access-matrix.md` (примечание к
> роли НФ), scope настраивается индивидуально через `user_scopes` —
> «только свой филиал» или «все филиалы», в зависимости от конфигурации
> учётной записи конкретного начальника филиала. По умолчанию — свой филиал.
>
> ⚠️ **(уточнить, известное ограничение реализации):** автоматического
> скоупинга по филиалу в списках сегодня нет — как и у остальных ролей,
> сужение выборки возможно только через фильтры UI; RBAC на уровне API
> отсутствует.

## Definition of Done
- Дашборд филиала отображает 4 ключевых показателя и график динамики
  направлений по статусам, агрегированные по всем лабораториям филиала (см.
  `../product/work-processes-by-roles.md`, раздел 6 «Главный экран»).
- Все действия создания/редактирования/командных переходов недоступны в UI
  для роли `branch_chief`.
- Уведомления о браке, отрицательном вердикте и просроченных дедлайнах
  приходят по SSE и корректно отмечаются прочитанными.
- `bun run lint typecheck build` зелёные; ролевой доступ проверен вручную по
  учётной записи `nachfil` / `nachfil123` (см.
  `../product/role-access-matrix.md`).
