# Роли системы

Процессные описания по каждой роли: **что** роль делает, **зачем** и **какими правами**
это подкреплено. Источник прав — [../product/role-access-matrix.md](../product/role-access-matrix.md)
(матрица `роль × ресурс × действие × scope`); источник процессов —
[../product/work-processes-by-roles.md](../product/work-processes-by-roles.md).

> Статус: индекс и шаблон (этап **A2.2** роадмапа). Отдельные файлы `<role>.md`
> заполняются при выполнении A2.2.

## Роли

| Файл | Роль | Ключ | Кратко |
|---|---|---|---|
| `registrar.md` | Регистратор | `registrar` | Приёмка: импорт/создание направлений и образцов, регистрация |
| `sanitary-inspector.md` | Санитарный врач | `sanitary_inspector` | Просмотр по своим объектам, санитарные заключения |
| `lab-assistant.md` | Ассистент лаборатории | `lab_assistant` | Просмотр рабочих объектов своей лаборатории |
| `lab-doctor.md` | Врач-лаборант | `lab_doctor` | Брак/показатели/комментарии/выпуск образцов |
| `lab-chief.md` | Начальник лаборатории | `lab_chief` | Всё врача + пост-выпуск правка (аудит) + показатели/цели своей лаборатории |
| `branch-chief.md` | Начальник филиала | `branch_chief` | Обзор по филиалу |
| `user-admin.md` | Администратор пользователей | `user_admin` | Пользователи, роли, права |

## Шаблон ролевого документа

```markdown
# <Роль> (<ключ>)

## Назначение
Одно-два предложения: кто это и зачем в процессе.

## Действия
Реестр действий с привязкой к ресурсам и статусным переходам (сверить с role-access-matrix).
| Действие | Ресурс | Право | Scope | Статусный переход |

## Сценарии
Пошагово: типовые рабочие сценарии роли (со ссылкой на flow/видео, если есть).

## Границы (scope)
Что видит/меняет (own / own_lab / own_branch / all) и почему.

## Definition of Done
Критерии готовности функционала роли (сверить с user-stories).
```
