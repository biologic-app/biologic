# Конвейер создания фич

Воспроизводимый процесс «issue → вертикальный слайс → видео». Каждая фича — вертикальный
слайс от frontend до backend, с записью видео. **Триггер задачи — детально оформленный
GitHub issue.** Соответствует этапу **A3** роадмапа.

## Стадии

Каждая стадия имеет явный выходной артефакт; при провале — возврат на предыдущую.

| # | Стадия | Что происходит | Артефакт | Агент/скилл |
|---|---|---|---|---|
| 1 | **План** | Исследование кодовой базы (codebase-memory) и документации → план вертикального слайса (FE↔BE), файл-уровень | план в `docs/features/<slug>/` | `feature-planner` |
| 2 | **Верификация плана** *(итеративно)* | Blast radius: что может сломаться; оценка архитектурных решений; правки плана до схождения | согласованный план | `critic` / `architect` |
| 3 | **Имплементация** | Вертикальный слайс: backend → SDK-regen → frontend | код | `ddd-executor` / `executor` |
| 4 | **e2e в изоляции** | k6 (API-контракт) + Playwright (UI) на отдельном стенде/worktree | зелёные e2e | `k6-*-authoring`, `playwright-cli` |
| 5 | **CI + PR** | Линтеры, тесты, sdk-contract на GitHub; открыть PR | зелёный CI + PR | — |
| 6 | **Цикл починки PR** | Пока красный CI не станет зелёным (повтор 3–5) | зелёный PR | — |
| 7 | **Ревью другой моделью** | Независимая проверка; в т.ч. **что старые тесты реальные** (не заглушены/не подогнаны) | вердикт ревью | `code-reviewer` / `/code-review ultra` |
| 8 | **Видео** | **ДО и ПОСЛЕ** для багфикса; **только ПОСЛЕ** для нового функционала | запись демо в PR | `flow-video-recorder` |

## Инварианты

- Изменение API ⇒ регенерация SDK (`bun run sdk:generate`) — часть DoD.
- Вертикальный слайс = один PR (монорепо).
- Conventional Commits (англ., ≤72 символа).
- Frontend — только явные импорты (см. корневой `CLAUDE.md`).

## Шаблоны

- GitHub issue template (фича/багфикс): контекст, роль, acceptance criteria, затрагиваемые
  экраны/эндпоинты, ссылки на `docs/`.
- PR template: чек-лист (план / верификация / тесты / линт / SDK-regen / видео).
- Скаффолд фичи `docs/features/<slug>/` (стадии `01-planning … 05-testing`).
