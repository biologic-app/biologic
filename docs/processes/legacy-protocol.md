# Формирование протокола: разбор старой программы

Разбор того, как **старая программа** формирует протокол испытаний из xlsx, чтобы
воспроизвести это в новой системе. Соответствует этапу **C4.1** роадмапа.

> Статус: **каркас** (C4.1). Исходники и шаблоны старой программы **доступны**
> (подтверждено владельцем). Первый шаг — получить их в репозиторий (`docs/legacy/`
> или отдельная папка) и заполнить разделы ниже фактами из кода.

## Что нужно выяснить

- [ ] Где лежат исходники старой программы и шаблоны xlsx (получить в репо).
- [ ] Какой шаблон xlsx используется (структура листов, ячеек, формулы, стили).
- [ ] Откуда берутся данные: направление → образцы → исследования → тесты → показатели.
- [ ] Как заполняются шапка/подвал (лаборатория, даты, номера, подписи).
- [ ] Правила форматирования значений (нормы, единицы, округление, «брак»).
- [ ] Как формируется **выписка** (C4.2) и что в неё входит (бракованные образцы).

## Текущая опора в новом бэкенде

- Excel-стек уже в зависимостях: `openpyxl`, `xlrd`, `xlwt` (`backend/pyproject.toml`).
- Импорт направлений из легаси-формата: `backend/.../legacy_direction_import.py`,
  `backend/.../direction_sample_import.py` — образец чтения xlsx.

## План воспроизведения (заполнить после разбора)

1. Зафиксировать шаблон и алгоритм заполнения (этот документ).
2. Реализовать генерацию протокола по шаблону на данных образцов/тестов/показателей.
3. Сверить вывод с эталоном старой программы (побайтово/по содержимому ключевых ячеек).
4. Выписка (C4.2) с бракованными образцами по своему шаблону.
5. *(research)* электронная подпись протокола (C4.3) — отдельно, вне MVP.
