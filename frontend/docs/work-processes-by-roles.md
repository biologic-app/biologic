# Процессы работы по ролям

---

## 1. Санитарный врач (СВ)

**Зона ответственности:** Сбор образцов на объекте и передача направления регистратору.

### Жизненный цикл работы
1. Выезжает на объект, собирает образцы.
2. Оформляет **направление в электронном виде** (во внешней системе или в файле установленного формата): объект, дата и время сбора, список образцов, дедлайны.
3. Доставляет образцы и электронное направление в филиал.
4. Регистратор импортирует направление — с этого момента санитарный врач может отслеживать статусы своих направлений (`draft` → `registered` → `in_progress` → `completed`) и образцов.
5. После завершения всех исследований просматривает готовые протоколы по своим направлениям.

### Доступ
- Просмотр направлений и образцов **только по своим объектам** (только чтение)
- Просмотр статусов исследований (только чтение)
- Просмотр протоколов, в которые входит хотя бы один его образец
- Получение и управление своими уведомлениями (прочитать / скрыть)

> ⚠️ Санитарный врач **не создаёт** направления в системе — импорт выполняет регистратор.

### Уведомления

| Уведомление | Важность |
|---|---|
| Образец признан браком | 🔴 Проблема |
| Дедлайн по направлению истёк | 🔴 Проблема |
| Направление зарегистрировано регистратором | 🔵 Информация |
| Дедлайн по направлению приближается | 🔵 Информация |
| Протокол готов к просмотру | 🟢 Успех |
| Направление выполнено | 🟢 Успех |

### Быстрые действия
- Перейти к списку своих направлений
- Открыть готовые протоколы
- Отметить все уведомления как прочитанные

### UI/UX ключевые экраны
- **Список направлений** — фильтр по объекту, дате, статусу; прогресс выполнения
- **Карточка направления** — текущий статус, список образцов и их статусы, ссылка на протокол
- **Лента уведомлений** — только свои уведомления

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| # | Метрика | Описание |
|---|---|---|
| 1 | Активных направлений | Направления в статусах `registered` / `in_progress` / `partially_completed` |
| 2 | Ожидают результатов | Образцы в статусе `in_progress` |
| 3 | Завершено за период | Направления в статусе `completed` |
| 4 | Готовых протоколов | Протоколы, доступные для просмотра |

**График:** динамика направлений по статусам (registered / in_progress / completed) по дням, неделям, месяцам, кварталам.

## 2. Регистратор (РЕГ)

**Зона ответственности:** Приёмка образцов, регистрация, ведение объектов, создание протоколов и заключений.

### Жизненный цикл работы

Регистратор работает по одному из двух сценариев:

#### Сценарий А — импорт направления
1. Принимает физические образцы и электронное направление от санитарного врача.
2. **Импортирует направление** из файла установленного формата — оно появляется в статусе `draft` со списком образцов.
3. Открывает направление в статусе `draft`:
   - Проставляет **типы образцов** для каждого образца.
   - Назначает **лаборатории** (цели исследования) — для каждого образца создаётся исследование в статусе `draft`.
   - Переводит направление в статус `registered`.
4. Регистрирует каждый образец: `pending` → `registered`, проставляет `received_at`, система вычисляет `deadline`.
5. При обнаружении брака переводит образец `pending` → `rejected` — все исследования образца автоматически переходят в `rejected`.
6. После завершения всех исследований и закрытия образцов формирует **протокол** и **заключение**.

#### Сценарий Б — ручное создание направления
1. Принимает физические образцы без электронного направления.
2. **Создаёт направление вручную** — указывает объект, дату и время сбора, дедлайны. Направление появляется в статусе `draft`.
3. Вручную **добавляет образцы** в направление.
4. Далее — аналогично шагам 3–6 сценария А.

#### Общий шаг для обоих сценариев
- Ведёт справочник объектов в рамках своего филиала.

### Статусы, которыми управляет регистратор

| Сущность     | Переход                  | Условие                                                 |
| ------------ | ------------------------ | ------------------------------------------------------- |
| Направление  | `—` → `draft`            | Импорт файла или ручное создание (IMP)                  |
| Направление  | `draft` → `registered`   | Проставлены типы образцов и назначены лаборатории (REG) |
| Образец      | `pending` → `registered` | Приёмка, проставлен `received_at` (REG)                 |
| Образец      | `pending` → `rejected`   | Брак при приёмке (REJ)                                  |
| Исследование | `draft` → `rejected`     | Регистратор убрал исследование (REJ)                    |

### Доступ
- Импорт и ручное создание направлений, редактирование в статусе `draft`
- Регистрация и отклонение образцов
- Назначение типов образцов и лабораторий
- Создание и редактирование протоколов и заключений
- Просмотр исследований и испытаний (только чтение)
- Ведение справочника объектов в своём филиале
- Получение и управление своими уведомлениями (прочитать / скрыть)

### Уведомления

| Уведомление                              | Важность      |
| ---------------------------------------- | ------------- |
| Образец просрочен (дедлайн истёк)        | 🔴 Проблема   |
| Образец признан браком в лаборатории     | 🔴 Проблема   |
| Дедлайн по образцу приближается (< 24 ч) | 🔵 Информация |
| Закрыт образец                           | 🟢 Успех      |

### Быстрые действия
- Импортировать новое направление
- Создать направление вручную
- Открыть очередь на приёмку (`draft`)
- Создать протокол по завершённому образцу

### UI/UX ключевые экраны
- **Очередь на приёмку** — список направлений в статусе `draft` / `registered` с индикацией дедлайнов
- **Карточка направления** — список образцов с возможностью проставить тип, назначить лабораторию, зарегистрировать или отклонить
- **Форма регистрации образца** — поле `received_at`, признак брака
- **Форма протокола** — конструктор заключения с шаблонными выводами

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| #   | Метрика                 | Описание                                        |
| --- | ----------------------- | ----------------------------------------------- |
| 1   | Ожидают приёмки         | Направления в статусе `draft`                   |
| 2   | Образцов на регистрации | Образцы в статусе `pending`                     |
| 3   | Просроченные дедлайны   | Образцы, у которых `deadline` < сегодня         |
| 4   | Готово к протоколу      | Направления в статусе `completed` без протокола |

**График:** динамика приёмки (зарегистрировано / отклонено / ожидает) по дням, неделям, месяцам, кварталам.

## 3. Врач-лаборант (ВЛ)

**Зона ответственности:** Подтверждение и проведение исследований и испытаний в своей лаборатории.

### Жизненный цикл работы
1. Видит список исследований в статусе `draft`, назначенных на его лабораторию.
2. Подтверждает исследование: `draft` → `ordered`, либо отклоняет `draft` → `rejected`.
3. Берёт исследование в работу: `ordered` → `in_progress`.
4. По каждому исследованию проводит **испытания**:
   - Берёт испытание в работу: `queued` → `in_progress`.
   - Вносит результат измерения: `in_progress` → `completed`.
   - При необходимости возвращает испытание в очередь: `in_progress` → `queued`.
   - При необходимости отклоняет испытание: `queued` / `in_progress` → `rejected`.
5. Когда все испытания завершены — система автоматически переводит исследование `in_progress` → `completed`.
6. Может отклонить образец при обнаружении брака: `pending` → `rejected`.

### Статусы, которыми управляет врач-лаборант

| Сущность     | Переход                               | Условие                  |
| ------------ | ------------------------------------- | ------------------------ |
| Исследование | `draft` → `rejected`                  | Отклонение (REJ)         |
| Исследование | `draft` → `ordered`                   | Подтверждение (CNF)      |
| Исследование | `ordered` → `in_progress`             | Взял в работу (STR)      |
| Испытание    | `queued` → `in_progress`              | Взял в работу (STR)      |
| Испытание    | `in_progress` → `completed`           | Внёс результат (RES)     |
| Испытание    | `in_progress` → `queued`              | Вернул в очередь (REQ)   |
| Испытание    | `queued` / `in_progress` → `rejected` | Отклонил (REJ)           |
| Образец      | `pending` → `rejected`                | Брак в лаборатории (REJ) |

### Доступ
- Просмотр образцов, исследований, испытаний **только своей лаборатории**
- Подтверждение / отклонение исследований (CNF / REJ)
- Управление испытаниями (STR, RES, REQ, REJ)
- Отклонение образца (брак)
- Получение и управление своими уведомлениями (прочитать / скрыть)

> ⚠️ Врач-лаборант **не управляет справочниками** показателей и целей исследований — это зона ответственности начальника лаборатории.

### Уведомления

| Уведомление | Важность |
|---|---|
| Дедлайн по образцу истёк | 🔴 Проблема |
| Образец признан браком (входящий) | 🔴 Проблема |
| Новое исследование назначено на лабораторию | 🔵 Информация |
| Дедлайн по образцу приближается (< 24 ч) | 🔵 Информация |
| Все испытания исследования завершены | 🟢 Успех |

### Быстрые действия
- Открыть очередь на подтверждение (`draft`)
- Открыть рабочую очередь (`ordered` / `in_progress`)
- Внести результат испытания
- Отклонить образец (брак)

### UI/UX ключевые экраны
- **Рабочая очередь** — исследования в статусах `draft` / `ordered` / `in_progress`, сортировка по дедлайну
- **Карточка исследования** — список испытаний с полями для ввода результатов, статус каждого испытания
- **Форма испытания** — показатель, норма, поле результата, вывод «соответствует / не соответствует»
- **Индикатор дедлайна** — цветовое кодирование (зелёный / жёлтый / красный)

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| # | Метрика | Описание |
|---|---|---|
| 1 | Ожидают подтверждения | Исследования в статусе `draft` |
| 2 | В работе | Исследования в статусе `in_progress` |
| 3 | Просрочено | Образцы, у которых `deadline` < сегодня |
| 4 | Выполнено за период | Исследования в статусе `completed` |

**График:** динамика исследований (подтверждено / в работе / выполнено / отклонено) по дням, неделям, месяцам, кварталам.

## 4. Ассистент-лаборант (АЛ)

**Зона ответственности:** Наблюдение за ходом работ в своей лаборатории (только просмотр).

### Жизненный цикл работы
1. Отслеживает текущее состояние образцов, исследований и испытаний в своей лаборатории.
2. Информирует врача-лаборанта или начальника лаборатории о проблемных позициях.

### Доступ
- Просмотр направлений, образцов, исследований, испытаний **только по своей лаборатории** (только чтение)
- Просмотр справочников: типы образцов, цели и показатели исследований
- Без права изменения статусов и данных

> ⚠️ Ассистент-лаборант **не получает уведомлений** и не имеет права на изменение каких-либо данных.

### Уведомления
Роль не получает уведомлений.

### Быстрые действия
- Перейти к списку активных образцов
- Перейти к просроченным исследованиям

### UI/UX ключевые экраны
- **Дашборд лаборатории** — сводка по активным образцам, статусам исследований, дедлайнам
- **Список исследований** — фильтр по статусу, дедлайну, образцу (только чтение)
- **Карточка образца** — детали образца и список исследований (только чтение)

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| # | Метрика | Описание |
|---|---|---|
| 1 | Активных образцов | Образцы в статусах `registered` / `in_progress` |
| 2 | Исследований в работе | Исследования в статусе `in_progress` |
| 3 | Просрочено | Образцы с истёкшим `deadline` |
| 4 | Выполнено за период | Исследования в статусе `completed` |

**График:** динамика исследований (в работе / выполнено / отклонено) по дням, неделям, месяцам, кварталам.

## 5. Начальник лаборатории (НЛ)

**Зона ответственности:** Управление работой лаборатории, ведение справочников, подтверждение исследований, финальное закрытие образцов.

### Жизненный цикл работы
1. Подтверждает или отклоняет исследования: `draft` → `ordered` / `rejected`.
2. При необходимости сам проводит испытания (замещает врача-лаборанта) — все действия ВЛ доступны.
3. После завершения всех исследований по образцу (статус `analyzed`) **закрывает образец**: `analyzed` → `completed`, устанавливает `verdict`.
4. Может назначить новые испытания — тогда образец автоматически возвращается `analyzed` → `in_progress`, а исследование `completed` → `in_progress`.
5. Ведёт справочники показателей (`indicators`) и целей исследований (`research_goals`) в своей лаборатории.
6. Получает уведомления о браке образцов и критических событиях.

### Статусы, которыми управляет начальник лаборатории

| Сущность     | Переход                               | Условие                        |
| ------------ | ------------------------------------- | ------------------------------ |
| Исследование | `draft` → `rejected`                  | Отклонение (REJ)               |
| Исследование | `draft` → `ordered`                   | Подтверждение (CNF)            |
| Исследование | `ordered` → `in_progress`             | Взял в работу (STR)            |
| Испытание    | `queued` → `in_progress`              | Взял в работу (STR)            |
| Испытание    | `in_progress` → `completed`           | Внёс результат (RES)           |
| Испытание    | `in_progress` → `queued`              | Вернул в очередь (REQ)         |
| Испытание    | `queued` / `in_progress` → `rejected` | Отклонил (REJ)                 |
| Образец      | `pending` → `rejected`                | Брак (REJ)                     |
| ==Образец==  | ==`analyzed` → `completed`==          | ==Закрытие с вердиктом (CLO)== |

### Доступ
- Все действия врача-лаборанта в своей лаборатории
- Закрытие образцов (`analyzed` → `completed`, CLO)
- Управление справочниками `indicators` и `research_goals` в рамках своей лаборатории (C,R,U,D)
- Просмотр всех образцов, исследований, протоколов лаборатории
- Получение и управление своими уведомлениями (прочитать / скрыть)

### Уведомления

| Уведомление | Важность |
|---|---|
| Дедлайн по образцу истёк | 🔴 Проблема |
| Образец признан браком | 🔴 Проблема |
| Вердикт «не соответствует» по закрытому образцу | 🔴 Проблема |
| Новое исследование назначено на лабораторию | 🔵 Информация |
| Дедлайн по образцу приближается (< 24 ч) | 🔵 Информация |
| Образец перешёл в статус `analyzed` — готов к закрытию | 🔵 Информация |
| Все испытания исследования завершены | 🟢 Успех |

### Быстрые действия
- Открыть очередь на подтверждение (`draft`)
- Открыть список образцов на закрытие (`analyzed`)
- Открыть рабочую очередь испытаний
- Перейти к справочнику показателей

### UI/UX ключевые экраны
- **Очередь подтверждения** — исследования в статусе `draft`, ожидающие подтверждения
- **Список образцов на закрытие** — образцы в статусе `analyzed` с возможностью установить вердикт и закрыть
- **Дашборд лаборатории** — активные образцы, просроченные дедлайны, исследования в работе
- **Карточка образца** — полная история исследований и испытаний, кнопка закрытия
- **Справочники** — управление показателями и целями исследований своей лаборатории

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| # | Метрика | Описание |
|---|---|---|
| 1 | Ожидают подтверждения | Исследования в статусе `draft` |
| 2 | Образцов на закрытие | Образцы в статусе `analyzed` |
| 3 | Просрочено | Образцы с истёкшим `deadline` |
| 4 | Браков за период | Образцы в статусе `rejected` |

**График:** динамика образцов (зарегистрировано / в работе / закрыто / брак) по дням, неделям, месяцам, кварталам.

## 6. Начальник филиала (НФ)

**Зона ответственности:** Контроль работы всего филиала, получение уведомлений о критических событиях.

### Жизненный цикл работы
1. Получает уведомления о критических событиях:
   - Образец признан браком (`rejected`)
   - Финальный вердикт по образцу — «не соответствует»
   - Просроченные дедлайны
2. Просматривает направления (`draft` → `completed`), образцы и протоколы по всем лабораториям своего филиала.
3. Не вмешивается в операционные процессы напрямую.

### Доступ
- Просмотр направлений, образцов, протоколов в рамках своего филиала (только чтение)
- Получение и управление своими уведомлениями (прочитать / скрыть)

> ⚠️ Начальник филиала **не имеет доступа** к исследованиям (`research`), испытаниям (`tests`), заключениям (`conclusions`) и лабораторным справочникам.

### Уведомления

| Уведомление | Важность |
|---|---|
| Образец признан браком | 🔴 Проблема |
| Вердикт «не соответствует» по закрытому образцу | 🔴 Проблема |
| Дедлайн по направлению истёк | 🔴 Проблема |
| Дедлайн по направлению приближается | 🔵 Информация |
| Направление выполнено | 🟢 Успех |

### Быстрые действия
- Открыть ленту уведомлений
- Перейти к просроченным направлениям
- Открыть список браков за период
- Перейти к выполненным направлениям

### UI/UX ключевые экраны
- **Дашборд филиала** — сводная статистика: активные направления, образцы по статусам, просроченные дедлайны
- **Лента уведомлений** — хронология критических событий с переходом к карточке образца
- **Список направлений и образцов** — просмотр по всем лабораториям филиала

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| # | Метрика | Описание |
|---|---|---|
| 1 | Активных направлений | Направления в статусах `in_progress` / `partially_completed` |
| 2 | Просрочено | Образцы с истёкшим `deadline` по всему филиалу |
| 3 | Браков за период | Образцы в статусе `rejected` |
| 4 | Выполнено за период | Направления в статусе `completed` |

**График:** динамика направлений по статусам (зарегистрировано / в работе / выполнено) по дням, неделям, месяцам, кварталам — по всем лабораториям филиала.

## 7. Администратор пользователей (АП)

**Зона ответственности:** Управление пользователями, ролями и областями видимости.

### Жизненный цикл работы
1. Заводит пользователей, назначает роли.
2. Настраивает области видимости (`user_scopes`) — привязывает пользователей к филиалам и лабораториям.
3. Управляет ролями и разрешениями (`roles`, `permissions`, `role_permissions`).

### Доступ
- Полное управление пользователями, ролями и разрешениями (C,R,U,D)
- Настройка областей видимости пользователей (`user_scopes`)
- **Нет доступа** к операционным данным (направления, образцы, исследования, протоколы)
- **Нет доступа** к лабораторным справочникам

> ⚠️ Администратор пользователей **не ведёт** лабораторные справочники — это зона НЛ (показатели, цели исследований) и РЕГ (объекты).

### Уведомления
Роль не получает операционных уведомлений.

### Быстрые действия
- Создать нового пользователя
- Назначить роль пользователю
- Настроить область видимости
- Перейти к пользователям без `user_scope`

### UI/UX ключевые экраны
- **Управление пользователями** — список, форма создания/редактирования, назначение роли и области видимости
- **Управление ролями** — список ролей и их разрешений

### Главный экран

**Период:** выбор интервала дат (день / неделя / месяц / квартал)

**4 ключевых показателя:**

| # | Метрика | Описание |
|---|---|---|
| 1 | Всего пользователей | Активные учётные записи в системе |
| 2 | Новых за период | Пользователи, созданные за выбранный интервал |
| 3 | Ролей в системе | Количество настроенных ролей |
| 4 | Без области видимости | Пользователи без настроенного `user_scope` |

**График:** динамика активности пользователей (создано / изменено / заблокировано) по дням, неделям, месяцам, кварталам.
